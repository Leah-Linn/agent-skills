# 岗位化表达逻辑

在 P1c 建 JD 回音矩阵、P3 写核心优势和经历、P4 做压力测试时读取本文件。

## 1. JD 回音矩阵

对每条 JD 职责依次处理：

1. 保留原句和关键词
2. 判断它要解决的业务问题，而不是只做同义改写
3. 合并重复职责，按重要性排序
4. 从素材库匹配 A 级直接证据或 B 级迁移证据
5. 用 JD 语言描述真实证据，不复制 JD 冒充既往职责

示例：

| JD 原句 | 业务目的 | 可用证据 |
|---|---|---|
| 负责区域客户跟进 | 建立管道并推动转化 | 客户分层、触达、需求确认、商机推进 |
| 制定并实施区域销售策略 | 找到增长点并分配资源 | 市场判断、目标拆解、渠道选择、复盘调整 |
| 发展渠道合作伙伴 | 建立覆盖并实现动销 | 代理筛选、签约、培训、库存与 sell-out 管理 |

## 2. 核心优势质量门槛

核心优势不是职责清单。每条至少命中一项，最好命中两项：

- **差异化**：候选人相对同类人的独特背景或资源
- **业务方法**：能够复述、拆解和迁移的方法
- **可验证结果**：有口径、有归因、有证据的结果

避免只写「商务沟通、客户维护、渠道拓展、市场调研」。把它们改造成更具体的能力命题，但不得超过事实：

| 基础说法 | 升级成立的条件 | 可用方向 |
|---|---|---|
| 商务沟通 | 确实跨语言或跨文化推进过业务 | 跨文化沟通 / 商务谈判 |
| 渠道拓展 | 覆盖线索、筛选、洽谈或签约中的多个环节 | 多渠道获客 / 签约闭环 |
| 客户维护 | 实际做过培训、动销、库存、售后或复购机制 | 渠道运营 / 客户成功 |
| 市场调研 | 从信息收集形成判断，并影响选择或动作 | 市场洞察 / 区域策略 |

不能满足升级条件时，不要直接把基础说法放进最终简历；先把它标记为「价值未挖完」，通过提问补出业务目的、判断、决策影响或阶段结果。补不出来时，退出核心槽位，而不是用弱表达凑版面。

## 3. 先拆语义角色，再决定标题

改写前必须先拆出四个不同角色，禁止边读边直接换词：

| 语义角色 | 回答的问题 | 常见内容 |
|---|---|---|
| 业务目的 | 为什么做？要解决什么业务问题？ | 判断资源投向、提高转化、缩短回款、降低流失 |
| 个人行动 | 具体做了什么？用了什么方法？ | 访谈、交叉分析、客户分层、英文触达、谈判 |
| 判断/产出 | 行动形成了什么认知或交付物？ | 市场判断、用户画像、需求结论、方案、规则 |
| 业务结果 | 判断或产出推动了什么变化？ | 资源调整、成交、进入测试、效率提升、风险降低 |

标题按以下价值层级选择：

`业务结果/决策价值 > 业务目的 > 方法或能力 > 单纯行动`

必须遵守：

1. 原标题已有证据支撑时，优先保留，不为追求“更职业”而随意换成泛词。
2. 原内容已形成判断并影响决策时，不得从「洞察、决策、资源调整」降级为「分析、管理、支持」。
3. 证据不足时不得直接交付泛化降级版本；指出缺失的是哪一环，并先引导用户补充。
4. JD 关键词只用于对齐，不覆盖原素材更强的价值层级。
5. 标题与正文必须同层：标题写「洞察」，正文必须出现判断及其决策影响；标题写「成交」，正文必须有真实成交结果。

### 「市场洞察」的判定

同时满足以下三项，才成立「市场洞察」：

1. 有事实、访谈、数据或市场信息作为输入；
2. 经过比较、归因或综合分析，形成超出信息描述的业务判断；
3. 判断影响了市场选择、资源配置、客户策略或下一步动作。

若当前素材只写了信息收集或数据整理，先追问它形成了什么判断、支持了什么选择、推动了什么变化。三项齐全时，保留「市场洞察」或使用更具体的结果标题；始终补不出价值证据时，不把该条放进核心槽位。

示例：

| 角色 | 内容 |
|---|---|
| 业务目的 | 判断海外开发资源应重点投入哪个市场 |
| 个人行动 | 交叉分析投放归因、付费用户画像与合作表现 |
| 判断/产出 | 欧美头部创作者报价虚高，优质资源已被竞品锁定 |
| 业务结果 | 推动团队将资源转向日韩高潜市场 |

可用标题：「市场洞察」或「高潜市场识别与资源调整」。

错误标题：「市场策略分析」。它只描述泛化行动，抹掉了已经成立的判断与资源决策价值，属于语义降级。

### 泛化行动词触发价值挖掘

看到「分析、管理、执行、跟进、协助、参与、支持、整理、调研、维护」时，不要直接润色或同义替换。把它视为素材尚未提炼完成的信号，从以下问题中选择信息增益最高的 1–3 个询问用户：

1. 这项行动最终服务了什么业务目标，或者避免了什么问题？
2. 你从中发现了什么别人未必能直接看出的规律、差异或机会？
3. 它支持了谁做什么选择、决策或资源调整？
4. 哪个指标、客户阶段、转化节点、成本、效率或风险因此发生变化？
5. 你是否形成了可以复用的模型、规则、流程、工具或判断标准？

提炼方向取决于答案，不按固定词表机械升级：

| 泛化行动 | 可能的专业价值方向 |
|---|---|
| 分析 | 市场洞察、增长机会识别、资源配置判断、风险识别 |
| 管理 | 客户分层经营、销售管道推进、机制搭建、交付保障 |
| 执行 | 关键节点推进、方案落地、转化达成、交付闭环 |
| 跟进 | 商机推进、决策链经营、测试转化、回款或复购推进 |
| 整理 | 决策信息底座、流程标准化、风险控制、效率机制 |

表格只提供追问方向，不授权凭空升级。专业化的本质是挖出行动背后的业务价值，不是把普通词替换成高级词。

## 4. 每段经历采用双层结构

### 第一层：岗位范围

用 1–2 句交代负责区域、客户类型、产品、销售模式和职责边界。只写确实承担的范围。

### 第二层：关键成果

选择 2–4 条与 JD 最相关的证据，用「目标—动作—结果」组织：

- **目标**：要解决什么业务问题或达成什么指标
- **动作**：本人具体采取什么方法，使用什么工具
- **结果**：产生什么业务变化，数字如何计算、如何归因

不是每条都必须机械套句式，但核心 bullet 必须同时包含三项。

## 5. 行动、能力与结果

「拜访客户、参加展会、整理名单、制作报告」只是行动。写入简历前继续追问：

1. 这个行动服务于什么目标？
2. 做法有什么判断或方法？
3. 最后推动了什么结果？

如果没有可量化结果，使用可验证的阶段成果：完成关键人建联、确认需求、进入测试、取得样机反馈、形成区域判断、推动下一决策节点。不要生成不存在的成交额或客户数。

## 6. 专业化不是术语膨胀

专业词必须压缩真实业务含义，而不是掩盖空白：

- 「全链路」要求确实覆盖多个连续环节
- 「体系搭建」要求形成可重复使用的流程、规则或工具
- 「闭环」要求从输入推进到明确结果或反馈
- 「主导」要求拥有关键决策权和主要责任
- 「增长」要求存在明确基准与变化口径

任何专业词都要能回答：「包含哪些环节？你负责哪一段？证据是什么？」

## 7. 改写前后语义回归检查

每条改写完成后，对照原素材逐项检查：

- 业务目的是否仍然相同？
- 个人行动是否仍然可归因？
- 原有判断或洞察是否被保留？
- 结果及其因果关系是否被保留？
- 标题的价值层级是否低于原文？
- 是否因机械嵌入 JD 词汇而丢失差异化？
- 是否仍有泛化行动词占据标题或核心价值位置？
- 如果信息不足，是否先引导用户补充，而不是直接交付弱版本？

任一项失败，撤回改写，重新从四槽卡开始，不在错误版本上继续润色。

## 8. 面试追问钩子

每条核心优势和核心 bullet 生成一个最可能的追问。只有候选人能说明以下内容时才保留：

- 真实场景和目标
- 本人职责边界
- 关键步骤和工具
- 难点、判断与取舍
- 结果口径与个人归因
- 复盘和可迁移方法

答不清时按顺序处理：补真实素材、降低动词强度、删除无法归因的数字、改为团队成果并写清个人贡献、删除该条。
