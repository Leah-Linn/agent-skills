# 海外销售简历定制化

## 这个 skill 解决什么

「海外销售」是岗位名，不是一份工作。同一个名字底下藏着几种能力模型互不相通的活——所以简历必须按岗位定制，不是包装术，是回答「你是不是我这一格的人」。

本 skill 把这件事流程化：**分求职类型 → 拆 JD → 定坐标 → 建回音矩阵 → 出画像卡 → 最大化重编排 → 证据分级 → 溯源与压力测试**。

**优化目标不是完成一份简历，而是提高获得面试的概率。** 每个核心槽位都必须让 HR 快速感知候选人的专业判断、业务价值和岗位适配；仅仅准确但平庸的行动描述不算完成。

## 大前提：根据个人经历写简历，也要认清简历的本质

简历不是人生档案或个人经历流水账，而是帮助候选人获得目标岗位面试的**岗位适配证明**。HR 首先判断的不是「你经历过多少事」，而是「现有证据能否说明你适合这一格岗位」。因此，不要平均呈现所有经历；围绕岗位筛选、重组并最大化表达真实能力证据。

采用社会化的岗位思维：

1. **一岗一版**：允许准备多份简历，每份只服务一个清晰岗位方向，并调整经历顺序、详略、关键词和能力证据。
2. **在能力基础上向外拓展**：向从业者了解真实工作流程，用 AI 补齐行业知识、拆解职责和模拟追问，再把自己确实做过的动作映射到岗位流程。
3. **所有事实必须可自证**：公司、岗位、项目、任职时间、职责、数字和成果必须真实，能回到素材库，并能在面试中讲清背景、动作、结果和复盘。
4. **相关性优先，但不以虚构换相关性**：不得把「面试过」写成「任职过」，不得延长工作时间，不得冒充参与过未参与的公司或项目，也不得让 AI 生成后直接当作亲身经历。

### 最大化表达的边界

| 可以做 | 不可以做 |
|---|---|
| 调整经历顺序、模块标题、详略和关键词 | 把「了解过」写成「负责过」 |
| 展开被原简历压缩掉的真实工作细节 | 把「协助」写成「独立主导」 |
| 把真实动作翻译成目标岗位的专业语言 | 把「面试过」写成「任职过」 |
| 写团队成果并明确个人贡献 | 延长或拼接任职时间 |
| 用访谈、调研和 AI 补充行业认知 | 虚构公司、客户、项目、业绩或数字 |
| 为不同岗位准备不同版本 | 把 AI 生成的流程直接冒充亲身经历 |

把经验缺口转化成可验证动作：

| 原始需求 | 可采用的做法 | 简历中的标注方式 |
|---|---|---|
| 不知道目标岗位具体做什么 | 访谈学长学姐、研究 JD 和公司资料、让 AI 拆流程 | 用于理解岗位，不直接写成个人经历 |
| 缺少正式工作经历 | 完成真实的模拟项目、案例分析、作品集或志愿项目 | 明确标注「模拟项目」「个人项目」「课程项目」 |
| 现有经历看起来不相关 | 提取可迁移动作，改写动词、顺序和强调重点 | 保留原公司、身份、时间、事实和结果 |
| 经历时间太短 | 强调单位时间内完成的任务、产出和学习速度 | 如实写起止时间，不延长任职时长 |

最终目标不是「看起来像做过」，而是让招聘方快速看到：**候选人真实做过什么、这些能力为什么能迁移、入职后能解决什么问题。**

## 首次使用：先建配置

复制 `config.example.md` 为 `config.md`，填入你自己的信息：素材库路径、原简历模板路径、求职背景。

**本 skill 不内置任何个人信息**，全部从 `config.md` 读取。若 `config.md` 不存在，先提示用户创建。

需要的配置项：

| 配置项 | 说明 |
|---|---|
| `素材库路径` | 简历素材母版，唯一素材来源 |
| `简历模板路径` | 原简历文件，用于测量槽位与字数预算 |
| `求职背景` | 毕业时间 / 校招或社招 / 目标行业 / 目标地区 / 所在城市 |
| `目标岗位与投递渠道` | 决定 JD 对齐、简历语言、附件版与平台版的输出方式 |

⚠️ 求职背景直接影响定制方向。尤其**校招 vs 社招 vs 实习**——写错了整份简历会投错池子。

## 主流程

### P0 · 求职类型与简历架构分流

先读 `config.md` 的 `求职类型`，再读 `references/slots.md` 的架构与注意力预算规则。不得用同一套结构同时处理校招、社招和实习：

- **社招**：优先呈现核心优势与近期、相关工作经历；教育背景压缩后置
- **校招**：优先呈现教育背景、实习/项目、可迁移能力与岗位认知
- **实习**：优先呈现教育背景、可立即上手的技能、项目/实践与可用时间

先输出一行架构决策：`求职类型｜模块顺序｜重点展开的 1–2 段经历｜准备压缩或删除的模块`。

### P1 · 拆 JD，定四轴坐标

读 `references/axes.md` 拿判定表。

对 JD 逐句提取关键词，映射到四个轴：

1. **渠道销售 还是 大客户销售**（判定标准：中间有没有代理商）
2. **出海阶段**（0-1 开荒 / 1-10 发展 / 10-100 稳定）
3. **终端是 B 还是 C**（⚠️ 这一轴只用来细分渠道销售）
4. **线索从哪来**（公司给 vs 自拓）

**每条判定必须标注信源**：依据 JD 里的哪一句原文，以及置信度（高/中/低）。不许凭感觉。

### P1b · 信号不足时兜底

任何一个轴判不出来（校招 JD 极常见），读 `references/sources.md`，按优先级去查：

1. 该公司的**社招岗** JD（社招写得比校招具体得多）
2. 官网：Distributor / Partner / Where to buy 页、案例页、Newsroom
3. 年报 / 财报（上市公司）：海外营收占比、分区域收入、海外子公司
4. 招聘平台上该公司的岗位结构（招不招 marketing / 售后 / 技术支持）

需要系统性做公司调研时，**调用 `company-research` skill**（若已安装），不要在这里重复实现。

兜底查到的东西同样要**给出信源**（URL 或页面名），并明确标注这是推断不是 JD 明写。

### P1c · 建立 JD 回音矩阵

读 `references/writing-logic.md`，不要只收集 JD 关键词；逐条识别职责背后的业务目的，并为它寻找个人证据：

| JD 职责原句 | 业务目的 | JD 原词 | 个人证据编号 | 证据等级 | 是否进入简历 |
|---|---|---|---|---|---|

合并同义或重复职责，按岗位重要性排序。没有 A、B 级证据的职责标记为空缺，不把目标岗位职责直接复制成既往经历。

### P2 · 输出「岗位画像卡」→ ⏸ 停下来等用户确认

**这是强制停顿点。坐标判错，后面全白改。**

画像卡格式：

```
## 岗位画像卡 · <公司> <岗位>

### 四轴坐标
| 轴 | 判定 | 依据 | 置信度 |
|---|---|---|---|
| 渠道/大客户 | ... | JD 原句 or 信源 | 高/中/低 |
| 出海阶段 | ... | ... | ... |
| 终端 B/C | ... | ... | ... |
| 线索来源 | ... | ... | ... |

### 这一格要什么人（能力优先级排序）
1. ...
2. ...

### JD 原词清单（改写时要对齐这些词）
...

### 不确定项 / 建议面试时问
- ...
```

输出后**停下来**，等用户确认或修正坐标，再进入 P3。

### P3 · 从素材库选料 + 重编排

读 `references/personas.md` 拿这个坐标格的能力优先级；读 `references/writing-logic.md` 拿核心优势与经历写法；读 `references/slots.md` 拿篇幅和字数预算。

1. **选料**：从素材库按坐标选条目
2. **先拆语义角色**：在接触 JD 改写词之前，标注每条素材的「业务目的｜个人行动｜形成的判断或产出｜推动的结果」，未完成标注不得起标题
3. **锁定价值锚点**：识别原素材已经成立的最高价值层级及关键词（如洞察、成交、资源调整），作为改写不可丢失项
4. **再换取景框**：在不改变价值锚点和因果链的前提下，换成目标坐标格的语言，对齐 P1 提取的 JD 原词
5. **放大个人贡献**：把团队背景、个人动作、使用工具和产生结果拆开，优先写个人可归因的部分
6. **调节动词强度**：按真实参与程度使用「主导 / 负责 / 执行 / 协助 / 参与 / 了解」，不得越级
7. **构造双层经历**：先用 1–2 句说明岗位范围，再用 2–4 条关键成果证明与 JD 的匹配
8. **卡字数**：每条 bullet 严格控制在预算内

⚠️ 事实不能变，变的只有动词、名词和强调重点。

### P3a · 核心优势与目标—动作—结果检查

- 每条核心优势必须至少体现一项：**差异化、业务方法、可验证结果**
- **严格区分目的与行动**：目的是「为什么做、要解决什么业务问题」，行动是「具体做了什么、用了什么方法」。不得用行动名称代替业务目的，也不得把目的改写成动作
- 每条素材先在内部形成四槽卡：`业务目的｜个人行动｜判断/产出｜业务结果`。核心 bullet 四项尽量齐全；事实缺失时允许留空，不得靠推测补齐
- 标题按价值层级选择：**业务结果/决策价值 > 业务目的 > 方法或能力 > 单纯行动**。最终投递版不得用「分析、管理、执行、跟进、协助、参与、支持、整理、调研」等泛化行动词单独充当标题或核心能力
- **把泛化词视为未挖完的报警器**：看到上述词，立即停止润色，转入价值挖掘；追问它服务了什么目标、形成什么判断、影响什么决策、推动什么增长或阶段变化、沉淀什么机制
- **禁止语义降级**：原素材已成立的「洞察、决策、增长、成交、资源调整、体系搭建」等价值表达，不得改成更泛的「分析、管理、参与、支持」
- **保留强表达优先于替换 JD 词**：JD 对齐只能改变取景框，不能抹掉候选人原有的更强业务价值。不得为了显得稳妥或贴关键词，把有判断和决策影响的内容改成泛化动作
- **信息不足时先引导用户，不输出弱版本**：从下列问题中选择信息增益最高的 1–3 个提问，等待用户补充后再定标题：①这项工作最终支持了什么选择或决策？②你发现了什么非显而易见的规律？③哪个指标、转化阶段或资源投向因此发生变化？④你建立了什么可复用机制？⑤如果不做，会造成什么业务问题？
- 「市场洞察」成立需同时满足：有事实或数据输入、形成超出描述层的业务判断、该判断影响选择或动作。三项齐全时应保留「市场洞察」或使用更具体的结果标题；缺项时先向用户追问对应信息，不直接用「市场调研」「数据分析」占据核心槽位
- 改写后必须保留因果链：`为了解决什么问题 → 做了什么 → 得出什么判断 → 推动什么变化`。不得调换、合并或删除关键语义角色
- **专业化标题不等于抬高参与程度**：标题写业务价值，正文仍须如实保留「主导/负责/执行/协助/参与」边界。可以把「协助分析」提炼为有证据的「机会识别」或「决策支持」，但不得把协助者写成决策者
- 每条核心优势都要形成一个候选人能够回答的面试追问钩子；答不清时先引导补充真实细节，仍无价值证据则退出核心槽位，不交付泛化行动标题

### P3b · 证据分级

对候选素材逐条评级：

| 级别 | 定义 | 使用规则 |
|---|---|---|
| **A · 直接证据** | 确实做过，能说明过程、工具、个人动作和结果 | 直接写入简历，优先占核心槽位 |
| **B · 迁移证据** | 业务场景不同，但关键动作或能力与岗位要求相同 | 岗位化改写，同时保留原场景和真实参与程度 |
| **C · 认知证据** | 只了解流程，尚未亲自执行 | 不得写成工作经历；用于求职信、面试认知，或转化成真实项目后再写 |

只允许 A、B 级证据进入经历 bullet。每条 bullet 在内部工作稿中标注证据等级。

### P3c · 能力外扩与补缺

当目标岗位要求没有 A、B 级证据时，按以下顺序处理：

1. 访谈从业者、研究 JD 和公司资料，还原真实工作流程
2. 让 AI 拆解流程节点、典型工具、交付物、指标和常见问题
3. 回素材库寻找动作相同、场景不同的迁移证据
4. 仍然缺失时，设计一个能实际完成的模拟项目、案例分析、作品集或志愿项目
5. 用户完成并提供过程与产物后，将其作为项目经历写入，并明确标注项目属性

不得把「计划完成」写成「已经完成」，也不得把研究得到的岗位流程写成亲身工作经历。

### P4 · 真实性溯源 + 面试压力测试（硬约束）

**这一步用于保证所有表达事实一致、可追溯、可自证，不许跳过。**

采用双门槛：**事实成立 + 面试可防守**。能答清楚不等于事实成立；事实成立但答不清，也不能直接进入投递版。

对每一条改写后的 bullet，检查：

- [ ] 能追溯到素材库里的**哪一条**原始条目？
- [ ] 出现的**每个数字**是否在素材库里存在？
- [ ] 有没有引入素材库里没有的事实、公司、职责、成果？
- [ ] 团队成果是否被错误归因为个人成果？
- [ ] 动词强度是否超过真实参与程度？
- [ ] 是否明确区分了业务目的和个人行动？
- [ ] 改写是否保留了原素材的判断、结果和因果链？
- [ ] 标题是否从「洞察/决策/结果」降级成了泛化的「分析/管理/执行」？
- [ ] 是否为了机械对齐 JD 关键词，丢失了原素材更强的业务价值？
- [ ] 标题或核心能力是否仍由「分析/管理/执行/跟进/协助/参与/支持/整理/调研」等泛化词主导？如是，是否已暂停输出并完成价值追问？

**规则（不可协商）：素材库里没有的数字和事实，一律不写。** 如果某个坐标格需要某条能力而素材库里没有对应素材，**如实指出这是空缺**，并建议用「认知层」补（见下），不要编。

对每条 bullet 连续追问：

1. 当时的业务背景和目标是什么？
2. 你的职责边界是什么？哪些不是你做的？
3. 你具体执行了哪几步，使用了什么工具？
4. 遇到的最大问题是什么，如何处理？
5. 结果如何计算，数字来源在哪里？
6. 团队成果中哪一部分可归因于你？
7. 如果重做一次，你会改变什么？

不能清楚回答时，依次处理：补充真实素材 → 降低动词强度 → 删除无法归因的数字 → 改写为团队成果并说明个人贡献 → 删除该条。不得生成虚假回答填补证据链。

输出**证据与压力测试表**：

| 简历上写的 | 证据级别 | 来自素材库 | 原始事实 | 参与边界 | 追问风险 | 处理结果 |
|---|---|---|---|---|---|---|

用户面试前过一遍这张表，确保回答与简历一致，并提前补齐讲不清的证据链。

### P5 · 输出

输出前设置**面试资格门槛**：

- 每个核心槽位的前半句必须回答「HR 为什么应该继续看这个人」，优先呈现洞察、决策、增长、成交、效率、风险、机制或关键阶段结果
- 不得把职责清单、动作流水账或泛化能力词当成成品
- 高优先级素材仍停留在泛化行动层时，先向用户提问并暂停该条定稿；不得为了凑齐版面交付弱版本
- 专业价值表达必须能回到真实行动和证据，不能只做高阶词替换

产出四份纯文本：

**① 附件简历版**：按槽位组织，对应原简历模板，方便逐条粘贴
每条标注字数，格式见 `references/slots.md`。

**② 平台纯文本版**：去除文本框、表格依赖和装饰符号，保留相同事实、关键词和模块顺序，方便复制到招聘平台

## 零经验候选人的三层定制（改动成本从低到高）

应届生经验层能改的有限，主力在后两层：

| 层 | 做什么 | 成本 |
|---|---|---|
| **词汇层** | 同一件事换成对方阶段的语言（0-1 写「开拓/从零/独立」，稳定期写「维护/管理/赋能/复购」） | 低 |
| **动作层** | 把经历映射到对方的流程节点（如对进代理商开发 P0–P7） | 中 |
| **认知层** | 露出你知道这家公司在哪一格。**完全不需要经验，只需要调研，是应届生性价比最高的差异化** | 高回报 |

## 底线

不编造。不虚构经历、数字、项目。

理由是实用的不是道德的：海外销售面试会往下追三层，编的撑不到第三层；行业圈子小，戳穿一次的代价远大于多约一个面试。

真实素材写不出来，通常不是素材不够，是**没提炼过**——这时候应该回素材库挖，或提示用户去补缺失的数字，而不是编。
