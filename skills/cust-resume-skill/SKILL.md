# 海外销售简历定制化

## 这个 skill 解决什么

「海外销售」是岗位名，不是一份工作。同一个名字底下藏着几种能力模型互不相通的活——所以简历必须按岗位定制，不是包装术，是回答「你是不是我这一格的人」。

本 skill 把这件事流程化：**拆 JD → 定坐标 → 出画像卡 → 重编排素材 → 溯源校验**。

## 首次使用：先建配置

复制 `config.example.md` 为 `config.md`，填入你自己的信息：素材库路径、原简历模板路径、求职背景。

**本 skill 不内置任何个人信息**，全部从 `config.md` 读取。若 `config.md` 不存在，先提示用户创建。

需要的配置项：

| 配置项 | 说明 |
|---|---|
| `素材库路径` | 简历素材母版，唯一素材来源 |
| `简历模板路径` | 原简历文件，用于测量槽位与字数预算 |
| `求职背景` | 毕业时间 / 校招或社招 / 目标行业 / 目标地区 / 所在城市 |

⚠️ 求职背景直接影响定制方向。尤其**校招 vs 社招 vs 实习**——写错了整份简历会投错池子。

## 主流程

### P1 · 拆 JD，定四轴坐标

读 `references/axes.md` 拿判定表。

对 JD 逐句提取关键词，映射到四个轴：

1. **渠道销售 还是 大客户销售**（判定标准：中间有没有代理商）
2. **出海阶段**（0-1 开荒 / 1-10 发展 / 10-100 稳定）
3. **终端是 B 还是 C**（⚠️ 这一轴只用来细分渠道销售）
4. **线索从哪来**（公司给 vs 自拓）

**每条判定必须标注信源**：依据 JD 里的哪一句原文，以及置信度（高/中/低）。不许凭感觉。

### P1b · 信号不足时兜底

任何一个轴判不出来（校招 JD 极常见），读 `references/sources.md`，按优先级去查：

1. 该公司的**社招岗** JD（社招写得比校招具体得多）
2. 官网：Distributor / Partner / Where to buy 页、案例页、Newsroom
3. 年报 / 财报（上市公司）：海外营收占比、分区域收入、海外子公司
4. 招聘平台上该公司的岗位结构（招不招 marketing / 售后 / 技术支持）

需要系统性做公司调研时，**调用 `company-research` skill**（若已安装），不要在这里重复实现。

兜底查到的东西同样要**给出信源**（URL 或页面名），并明确标注这是推断不是 JD 明写。

### P2 · 输出「岗位画像卡」→ ⏸ 停下来等用户确认

**这是强制停顿点。坐标判错，后面全白改。**

画像卡格式：

```
## 岗位画像卡 · <公司> <岗位>

### 四轴坐标
| 轴 | 判定 | 依据 | 置信度 |
|---|---|---|---|
| 渠道/大客户 | ... | JD 原句 or 信源 | 高/中/低 |
| 出海阶段 | ... | ... | ... |
| 终端 B/C | ... | ... | ... |
| 线索来源 | ... | ... | ... |

### 这一格要什么人（能力优先级排序）
1. ...
2. ...

### JD 原词清单（改写时要对齐这些词）
...

### 不确定项 / 建议面试时问
- ...
```

输出后**停下来**，等用户确认或修正坐标，再进入 P3。

### P3 · 从素材库选料 + 重编排

读 `references/personas.md` 拿这个坐标格的能力优先级；读 `references/slots.md` 拿字数预算。

1. **选料**：从素材库按坐标选条目
2. **换取景框**：同一事实，换成这个坐标格的语言。对齐 P1 提取的 JD 原词
3. **卡字数**：每条 bullet 严格控制在预算内

⚠️ 事实不能变，变的只有动词、名词和强调重点。

### P4 · 真实性溯源校验（硬约束）

**这一步是「让人找不到马脚」的技术实现，不许跳过。**

对每一条改写后的 bullet，检查：

- [ ] 能追溯到素材库里的**哪一条**原始条目？
- [ ] 出现的**每个数字**是否在素材库里存在？
- [ ] 有没有引入素材库里没有的事实、公司、职责、成果？

**规则（不可协商）：素材库里没有的数字和事实，一律不写。** 如果某个坐标格需要某条能力而素材库里没有对应素材，**如实指出这是空缺**，并建议用「认知层」补（见下），不要编。

输出**溯源表**：

| 简历上写的 | 来自素材库 | 原始事实 | 被追问时怎么答 |
|---|---|---|---|

用户面试前过一遍这张表，就不可能被问穿。

### P5 · 输出

产出两份纯文本：

**① 按槽位组织的文本**（对应原简历模板的结构，方便逐条粘贴）
每条标注字数，格式见 `references/slots.md`。

**② 溯源表**（P4 的产物）

同时给一段**改动说明**：这一版相对原简历改了什么、为什么这么改、对应坐标的哪一条。

## 零经验候选人的三层定制（改动成本从低到高）

应届生经验层能改的有限，主力在后两层：

| 层 | 做什么 | 成本 |
|---|---|---|
| **词汇层** | 同一件事换成对方阶段的语言（0-1 写「开拓/从零/独立」，稳定期写「维护/管理/赋能/复购」） | 低 |
| **动作层** | 把经历映射到对方的流程节点（如对进代理商开发 P0–P7） | 中 |
| **认知层** | 露出你知道这家公司在哪一格。**完全不需要经验，只需要调研，是应届生性价比最高的差异化** | 高回报 |

## 底线

不编造。不虚构经历、数字、项目。

理由是实用的不是道德的：海外销售面试会往下追三层，编的撑不到第三层；行业圈子小，戳穿一次的代价远大于多约一个面试。

真实素材写不出来，通常不是素材不够，是**没提炼过**——这时候应该回素材库挖，或提示用户去补缺失的数字，而不是编。
